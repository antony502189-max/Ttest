# Оплата через Stripe Checkout: первая версия

Пошаговая проверка в изолированной локальной песочнице: [stripe-local-sandbox.md](stripe-local-sandbox.md).

Подключены оплата закрепления объявления в главном фотоблоке за **60 € на один календарный месяц**, покупка баннера по **1 € за день с выбором срока от 10 дней**, а также существующие пакеты TOP. На главной странице доступны семь мест для баннеров и одно место для закреплённого объявления. Подробности: [homepage-advertising.md](homepage-advertising.md).

## Как подготовить тестовую оплату

1. Применить `alembic upgrade head`: `0057_payment_orders` добавляет заказы, `0058_advertising_waitlist` — подписки на освобождение места.
2. Заказчик создаёт аккаунт Stripe и даёт технический доступ к **тестовому режиму**. Секретные ключи нельзя размещать в коде или отправлять в переписке.
3. В закрытых настройках сервера указать `STRIPE_SECRET_KEY` с префиксом `sk_test_` и `STRIPE_WEBHOOK_SECRET` с префиксом `whsec_`. Первый ключ позволяет создать страницу оплаты; второй нужен для проверки уведомления о результате.
4. В Stripe настроить отправку событий `checkout.session.completed`, `checkout.session.async_payment_succeeded` и `checkout.session.expired` на адрес `https://<АДРЕС_API>/api/v1/payments/stripe/webhook`. Для локальной проверки потребуется доступный Stripe адрес сервера или пересылка событий через Stripe CLI.
5. Указать в `FRONTEND_APP_URL` адрес сайта, на который покупатель вернётся после оплаты.
6. Новые баннеры стоят **1 € в день, минимум 10 дней**. Закрепление на главной стоит **60 € за месяц**. TOP стоит **30 € за календарный месяц**. `ADVERTISEMENT_30D_PRICE_CENTS` используется только для прежних пакетов баннеров на 30 дней. Старые оплаченные дневные пакеты TOP сохраняют купленный срок. В тестовом режиме деньги не списываются.

При локальном запуске через Docker Compose эти настройки берутся из корневого файла `.env` (он не добавляется в Git), а не из `backend/.env.example`. На VPS они берутся из закрытого `/srv/112233.es/shared/production.env`. Тестовый ключ следует использовать только локально или на отдельном тестовом стенде: публичный сайт с тестовым ключом позволил бы посетителям активировать услуги без реальной оплаты.

Тестовые и боевые ключи Stripe различаются. Боевые платежи дополнительно заблокированы настройкой `STRIPE_LIVE_PAYMENTS_ENABLED=false`. Включать их можно лишь после проверки аккаунта заказчика, правил возврата и успешной проверки обоих сценариев. [Тестовые карты Stripe](https://docs.stripe.com/testing).

## Что происходит после оплаты

- Сайт сохраняет заказ: покупателя, услугу, срок, сумму, номер платёжной страницы Stripe и состояние оплаты.
- Покупатель платит на странице Stripe. Сам возврат на сайт **не подтверждает оплату**: сервер проверяет подписанное уведомление либо читает настоящий статус сессии из Stripe API. Повторы не включают услугу второй раз.
- Оплаченный баннер поступает на проверку администратору. Выбранный срок начинается после одобрения.
- Закреплённое объявление включается после подтверждения оплаты на один календарный месяц. Место резервируется при открытии оплаты и не может быть одновременно продано другому покупателю.
- Оплаченный TOP включается или продлевается на один календарный месяц и поднимается выше объявлений без TOP. Среди объявлений с TOP выше располагается последнее оплаченное поднятие. Если у объявления сохранилось старое бессрочное поднятие, новая покупка блокируется до проверки поддержки.

## Ограничения этой версии

- Следующий этап тарификации комнат: первые 5 объявлений пользователя бесплатны, начиная с 6-го публикация оплачивается по индивидуальной цене. Цена и порядок покупки пока не определены, поэтому это правило ещё не включено в оплату.
- Если после оплаты баннер или объявление удалены, отменены либо больше не подходят для размещения, заказ отмечается для ручной проверки и возможного возврата. Возврат пока выполняется в кабинете Stripe.
- Рекламное место резервируется при создании платёжной сессии. При семи занятых местах новые покупки отклоняются до создания платежа. Пользователь может подписаться на освобождение места.
- При повторном открытии оплаты сайт использует прежнюю незавершённую платёжную страницу. Старую неоплаченную сессию с прежним тарифом можно отменить кнопкой «Отменить оплату» и открыть новый месячный TOP.
- Старый маршрут имитации оплаты доступен лишь в непроизводственном окружении без ключа Stripe. При настроенном Stripe он не может отметить кампанию оплаченной.

## Что ещё проверить перед включением настоящих денег

Создание и отмену платежа, успешный платёж по каждому виду услуги, повторное уведомление, ошибку оплаты, доступность рекламного места, возврат и сверку заказов с кабинетом Stripe. После этого утвердить цены и правила возврата с заказчиком.
