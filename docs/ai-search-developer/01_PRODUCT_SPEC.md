# 01 — Утверждённый продуктовый scope AI-поиска

> **Приоритет:** прямые решения владельца от 25.10.2026 выше автоматически сгенерированной «редакции 3» заказчика, предыдущих опросников и старого roadmap. Если старые документы противоречат этой странице — применяйте этот scope, фиксируйте конфликт в PR, не делайте лишнюю разработку.

## In scope

Пользователь набирает текст или записывает голос («комната для нас двоих с маленькой собакой до 700 € в Адехе»). После остановки записи ASR переводит аудио в текст. Серверный LLM преобразует текст и текущие параметры диалога в **строгий структурированный intent**. Сервер выполняет предсказуемый поиск по каталогу, сохраняет прежний список/карточки и возвращает краткий текст с подтверждёнными причинами. Follow-up «теперь только с балконом» заменяет лишь указанное ограничение.

Учитывать: состав проживающих (взрослые/дети/пара/друзья), максимальную проверенную вместимость, цену и период оплаты, город/район, room/studio/другие **фактически поддерживаемые** категории, short/long rental, животных с условными ограничениями, курение внутри/снаружи, удобства, балкон/террасу, known/unknown/conflict, актуальность.

Неподтверждённое разрешение **нельзя** выдавать за подтверждённое. Обязательные несовместимости исключаются; unknown/conditional показывать отдельно и честно («нужно уточнить») при соответствующей бизнес-логике. Не делать скрытого ослабления hard constraints.

## Окончательные пользовательские решения

| Тема | Утверждено |
|---|---|
| Доступ гостя | 3 успешных обращения к AI в календарные сутки |
| Доступ после входа | 200 успешных обращений к AI в календарные сутки |
| Сброс | Каждый день в 00:00 по `Europe/Madrid` (учёт DST; не rolling 24h) |
| Каналы | Голос + текст; общий счётчик, одна завершённая операция = один debit |
| Ответы | **Только текст**, плюс существующие listing cards |
| Голос | После завершения записи, без live transcription; распознанный текст можно исправлять |
| После лимита | Обычный ручной поиск всегда доступен; AI сообщает об исчерпании |
| Сохранение поисков / уведомления | **Только после регистрации**, reuse существующего SavedSearch/notifications |
| TOP, реклама, boosts | **Не менять** оплаченную коммерческую сортировку и placements |
| Карточки | **Сохранять как есть**, native/external/gallery/redirect/favorites |
| Карта | Существующую карту сохранить без изменений |
| Вакансии/работа | **Полностью исключить** |
| Новые карты/маршруты/POI | **Исключить**; без Places/Routes/travel time/районных рекламных фактов |
| Месячный spending cap | **Не устанавливать**; сохранять мониторинг и технические anti-abuse границы |
| Локальные LLM на VPS | Не нужны; inference по внешним API |

Сбои внутреннего ASR/LLM/SQL **не списывают** бизнес-квоту. Follow-up user message = новое обращение. ASR+LLM в одном голосовом обращении **не считаются двумя** пользовательскими запросами. Бесполезные бесконечные транскрипции без query ограничиваются техническим rate limit.

## Уровень источников и карточек

Не менять текущие preview-карточки сторонних объявлений и поведение перехода на внешнюю площадку. Не предполагать при этом, что ссылка сама по себе решает все вопросы лицензирования/ToS — это отдельный юридический review. Search result может использовать existing ListingCardResponse и короткие проверенные reason codes; не генерировать галерею и цены LLM.

Сохранять правила 1000 €/месяц для long-term и независимую туристическую категорию. В каталоге реально встречаются one-bedroom apartments, поэтому **не писать AI API с жёстким enum «только комнаты и студии»** без аудита текущих типов.

## Уточнения AI

В раннем клиентском ТЗ рекомендуется задавать минимум вопросов. Практическое правило: выполнять поиск сразу, если определены достаточные ограничения; задавать до 1–2 необходимых уточнений, когда без ответа нельзя безопасно построить критерий. Не запрашивать курение/животных/детей навязчиво при каждом запросе.

## НЕ выполнять без нового согласования

- Реализацию поиска вакансий или карьерных рекомендаций.
- Изменение TOP, платных рекламных показов, сортировки promotions.
- Прямой AI-поиск в интернете, live crawling при каждом запросе.
- Новую карту, маршрут до работы/университета, time-to-POI и внешние карты.
- Streaming/transcription text во время говорения, TTS.
- Автоматическое сохранение исходных аудио/диалогов в пользовательский профиль.
- Месячный жёсткий лимит денег.
- Замену существующих карточек или массовую перезапись imported listings.
- Принудительное расширение туристической юридической валидации без проверки закона и правил категории.

## Открытые вопросы = engineering gates, не повод переписывать scope

1. Юридические детали регистрации tourist rentals, включая rooms и даты заезда/выезда: пока не подтверждены. Не отменяет действующие правила публикации.
2. Terms/DPA/хранение данных у Groq/DeepSeek/OpenAI, особенно контакты из descriptions и аудио; требуется privacy approval до paid pilot.
3. Подтверждённые требования по scoring/UX-процентам отсутствуют; **не показывать фиктивные «92%»**. Лучше verified reason codes, пока не утверждена проверяемая метрика.
4. Эквивалентное время сброса гостей на Canary Islands: утверждён `Europe/Madrid`, UX должен это объяснять.
5. Практическая демонстрация смешанной речи RU/ES/EN через ASR benchmark до выбора production fallback.

Никаких других блокирующих вопросов для **офлайн ADR/DTO работ** сейчас нет.
