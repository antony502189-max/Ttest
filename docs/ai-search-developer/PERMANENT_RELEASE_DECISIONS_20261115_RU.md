15 ноября 2026. Пакет решений, **не конфигурация активации**.
Единственный порядок работ и критерии выхода: [канонический план](../ai-search-completion-plan.md).

**Решение владельца в этом чате:** $50/месяц и$5/сутки без автопополнения
одобрены после реализации/проверки постоянного ledger. Выбраны собственные объявления

Ответ по account/provider условиям отложен владельцем. Это не снимает B2/B4,

Работающий выпуск: primary `42ea90cb`, isolated issuer/ASR `50112a9e`, schema0080.
Составные условия, голос, сохранение и in-app уведомления проверены в согласованном

рабочий каталог с районами/вместимостью/датами и полная нагрузочная приёмка ещё не доказаны.

## 1. Предлагаемое постоянное ограничение расходов

Предлагается **$50 за календарный месяц и $5 в сутки**, без автоматического
пополнения/увеличения, для intent API. День и месяц считать в Europe/Madrid,
так же, как пользовательские квоты. Это предлагаемые суммы; владелец может
задать другие. До его решения прежний cumulative50attempts/$1 действует только
до `2026-11-15T20:59:59Z` и не превращается в этот бюджет.

На15ноября [официальный тариф](https://api-docs.deepseek.com/quick_start/pricing/)
для `deepseek-flash`: peak cache-miss input$0.30/1M, output$1.20/1M.
Скидки cache/off-peak в разрешение расходов не закладывать. Текущие потолки
32768input/1024output резервируют11060microUSD на **HTTP-попытку**, включая
повтор/ошибку с неизвестным результатом. Предложение допускает максимум452попытки
за день и4520за месяц при этих неизменных потолках; один запрос с повтором
может потребовать две попытки. Это верхняя граница, не прогноз посещаемости,
не число гарантированно успешных поисков и не счёт провайдера.

Сохранить guest3/auth200 успешных операций в сутки, существующие idempotency,
identity ownership и отсутствие debit для ошибки/clarification/no coverage.
Глобальный денежный предел может остановить новые AI-операции раньше личной квоты.
Сохранённые результаты, ручной поиск и SQL-only saved notifications продолжают
работать без модели. Локальный ASR не передаёт аудио внешнему провайдеру;
серверные расходы в эти$50 не входят.

Перед активацией постоянного режима требуется отдельная проверенная реализация:
атомарное резервирование дневного **и** месячного бюджета перед каждым IO,
durable receipt и unknown-usage halt, recovery/concurrency/границы DST,
aggregate alert на80% и100%, проверка тарифа/model identity и kill switch.
Текущий PilotBudget этого постоянного календарного режима не реализует.
Старый journal/binding/30attempts и все ключи сохранять; не создавать пустой
journal ради нового остатка. Перенос в новый ledger — проверяемый импорт с
сохранением исходного журнала и расхода текущего календарного периода.
Внешний account spending/balance limit проверять отдельно: application reservation
сама по себе не доказывает жёсткий предел счёта у провайдера.

**Суммы одобрены:** $50/месяц и$5/сутки без автопополнения. Ещё нужны
ответственный за account/оплату и account limits. Обычные code/test/fix/merge/deploy
разрешения повторно не запрашиваются.

## 2. Провайдер и исходящие данные

Технически предлагается сохранить текущий `deepseek-flash` для интерпретации
жилищных условий и локальный ASR. Это сохраняет существующий adapter/telemetry,
но не снимает account/privacy gate. Официальная страница сейчас указывает
model version `DeepSeek-V4.1-Flash-1017`; alias может измениться. Перед выпуском
нужно повторить exact-model semantic acceptance, а не переносить старые PASS.

[Open Platform Terms](https://cdn.deepseek.com/policies/en-US/deepseek-open-platform-terms-of-service.html)
от29апреля2026 определяют API/downstream application relationship.
[Privacy Policy](https://cdn.deepseek.com/policies/en-US/deepseek-privacy-policy.html)
от10февраля2026 прямо исключает правила обработки данных конечных пользователей
downstream-приложений из своей области. Поэтому эта публичная страница не
подтверждает условия именно нашего API account. Предыдущий
[account review](DEEPSEEK_OUTBOUND_POLICY_RU.md) остаётся BLOCKED.

Предлагаемый payload: только нормализованные жилищные условия/текущие typed criteria,
фиксированная схема и инструкции. Без аудио, исходной биографии/контактов,
user/session/result IDs, IP браузера, cookies, токенов, объявлений, source HTML/URL
и SQL. Дополнительные данные не следует «очищать» одним regex. Необработанные
непонятные фразы должны остаться локально и дать уточнение; arbitrary raw text
остаётся запрещённым до доказанной минимизации и account approval.

**Нужные сведения владельца, без ключей/паролей:** кто владеет API account и
несекретная account reference; применимый договор/DPA или ссылка на account terms;
регион обработки/subprocessors/условия передачи; training exclusion именно для API;
retention input/output/logs/backups и deletion SLA/процедура подтверждения удаления.
Если эти условия не удаётся подтвердить, выбрать provider/account с проверяемыми
условиями. Внешних писем провайдеру этот пакет не отправляет.

## 3. Постоянные данные и неподтверждённые условия

Предлагаемый порядок подключения данных: сначала собственные опубликованные
объявления сайта с явно заполненными полями; затем источники, на регулярное
обновление которых у оператора есть подтверждённое право и точный source profile.
Текущие13approved objects сохраняются. Найденные read-only66active Piso sources /
29objects, из них18objects хотя бы с одним fresh source на предыдущем checkpoint,
не являются разрешением на расширение и не доказывают all-authority eligibility.

| Условие | Необходимый источник факта | Что запрещено подставлять |
| --- | --- | --- |
| Район | Явное source/native поле + reviewed municipality/zone identity | Район из названия города, ближайшей точки или похожего имени |
| Число жильцов | Вместимость именно сдаваемой единицы и свободные места, policies для children/couple/friends | Число комнат, жителей всей квартиры или legacy default |
| Даты | Полные даты с годом, интервал доступности и применимые ограничения срока | Текущий/следующий год из «13сентября» |
| Срок | Явные min и max с единицами | Бесконечный max из «indiferente» или перевод месяцев в ночи |
| Курение | Явная policy с областью действия | Разрешение на балконе из отсутствия запрета или общий positive без scope |

Новый extractor v2 может обоснованно представить «no se permite fumar» как
запрет **внутри** жилья. Это не подтверждает outdoor/balcony permission и не
закрывает party/date/district gaps. Source snapshot CAS, неизменные original
payload/timestamps, all-authorities barrier и24h freshness сохраняются.

Предлагаемые постоянные эксплуатационные bounds для первоначального source
profile: существующий100sources/tick bound, refresh только через разрешённый
detail importer, backoff на403/429, без обхода access controls; текущая проверка
content freshness≤24h. Момент extraction не обновляет возраст upstream content.
Числа должны соответствовать source terms/rate limits; это не новый crawl-допуск.

**Выбор владельца:** собственные объявления иPisoCompartido. Ещё нужны
ответственный за актуальность/право обновления, для внешнего источника —
обещанные договор/feed/API/другое основание и разрешённый объём.
При отсутствии данных интерфейс обязан честно показать отсутствие покрытия,
сохранить hard-условия и не превращать запрос в price-only.

## 4. Что остаётся за разработкой

После решений: постоянный ledger/config, source mappings и standing refresh,
semantic/privacy negative tests, приёмка регистрации/письма с предоставленным
контролируемым адресом, human mic RU/ES/EN и независимые browser engines.
Письма на произвольные адреса не отправлять. Ранее удалённый QA account не
восстанавливать. Chrome и Edge используют Chromium; их PASS не доказывает WebKit/Firefox.

S5 capacity ISSUE-004 и исходные A10 пороги остаются обязательными; большие
100k/500k/1m прогоны ранее явно отложены и этим пакетом не разрешаются.
После применимой приёмки — exact-main release/rollback/наблюдение и S7.
Ответ владельца на бюджет/provider/data не заменяет эти доказательства.
