## 0. Решения владельца проекта (после анализа клиентского ТЗ)

> **Эти решения владельца проекта имеют приоритет над ранее пересланной редакцией заказчика** в частях, где они расходятся. Не трактовать оставленные в исходном отчёте требования о POI/маршрутах, изменении TOP, live ASR и вакансиях как задания на реализацию.

| Вопрос | Принятое решение | Последствие |
|---|---|---|
| Поиск работы / вакансий | **Исключён полностью** | Не создавать jobs/data ingestion/вакансии и не брать модуль вакансий из чужого демо |
| Сторонние карточки | **Сохранять существующие карточки и их переходы, 1:1** | Без переделки внешней preview/маршрутизации; юридический аудит источников остаётся отдельной необходимой проверкой |
| Платный TOP | **Существующая бизнес-логика без изменений** | Не создавать новый TOP-блок/новое placement правило в AI; не нарушать оплаченные позиции. Уточнить совместимость AI-порядка с существующим promotion tier на этапе алгоритма |
| Распознавание речи | **Только после завершения записи** | Batch ASR, не realtime streaming; текст можно исправить, запрос повторить |
| Новые карты, POI и маршруты | **Полностью исключены из scope** | Не подключать Places/Routes/POI, travel times, дороги до работы/учёбы или географические описания карточек. **Существующую карту объявлений оставить без изменений** |
| Анонимные обращения | **3 пользовательских обращения в сутки без регистрации** | Общий счётчик для текстовых и голосовых сообщений; после лимита подсказать время обновления и предложить авторизацию; обычный поиск не ограничивать |
| Сброс дневных лимитов | **Каждую ночь в 00:00 по материковой Испании (`Europe/Madrid`)** | Ежедневный календарный сброс для гостей и зарегистрированных; не скользящие 24 часа. Учитывать переход летнего/зимнего времени и корректно показывать `resets_at` |
| Авторизованные обращения | **200 AI-обращений в сутки** | Квота по server-side `user_id`, единая для голоса и текста; после исчерпания сохраняется обычный поиск |
| Сохранённые поиски и уведомления | **Только для зарегистрированных пользователей** | Повторно использовать существующую механику Ttest и её авторизацию; незарегистрированным показывать предложение войти |
| Ответы помощника | **Только текстом** | Не подключать TTS, голосовые ответы, speech-to-speech или дополнительный audio streaming |
| Месячный бюджет AI API | **Отсутствует; не задавать месячный spending cap** | Не блокировать сервис по выдуманному пределу €20/50/100; сохранять технические меры антиабуза, тайм-ауты и мониторинг потребления без искусственного месячного стоп-лимита |
| Туристическая аренда: дополнительные требования | **Решение пока неизвестно** | Сохранять существующую логику; пройти отдельный правовой/продуктовый review, не вводить новые правила без него |

**Лимит гостей (окончательное продуктовое решение):** без регистрации доступны **3 обращения к AI-помощнику за календарные сутки**; одна текстовая отправка или завершённая голосовая запись с обработкой = **1** обращение; follow-up («теперь дешевле») — отдельное обращение; системные ответы не считаются. Ошибочные обращения из-за сбоя сервиса/ASR не должны уменьшать квоту. Не считать ASR и LLM одного голосового сообщения отдельными обращениями. Сброс **ежедневно в 00:00 Europe/Madrid**, включая сезонный переход времени; сервер хранит абсолютный `resets_at` и вычисляет соответствующий календарный день; backend счётчик атомарен, анонимный идентификатор cookie + противодействие обходам без навязчивой fingerprinting. После 3 обращений предложить войти/зарегистрироваться **либо повторить завтра**. Обычный поиск остаётся бесплатным и доступным.

**Формат ответа:** только текст и существующие карточки. Голос пользователя принимается как запись, распознаваемая **после её завершения**. Не реализовывать TTS, live transcription или streaming speech-to-speech.

**Бюджет:** **не устанавливать месячный spending cap / quota по сумме денег**, как прямо указано владельцем. Техническое ограничение злоупотреблений, ограничение длительности аудио и size, тайм-ауты, логирование объёма токенов/расходов сохраняются как меры эксплуатации, но ни одна из них не должна неявно останавливать AI по достижении месячной суммы. Стоимость платных API всё равно измерять и показывать в observability.

**Квота авторизованных пользователей:** **200 пользовательских AI-обращений в сутки**, независимо от канала (текст/голос). Учет успешного обработанного сообщения = один запрос; уточняющая реплика расходует ещё один; ошибки наших API/провайдера не расходуют. Проверка лимита до платных API, атомарная резервация при параллельных запросах, idempotency для повторной отправки, возврат резервации при сбое. Время сброса календарных суток **согласовано: 00:00 Europe/Madrid** для всего сайта; не путать с плавающими 24 часами. Прежний лимит 3/сутки для гостей не меняется. По достижении лимита оставлять бесплатный обычный поиск и сообщать о следующем сбросе. Сохранённые поиски и уведомления доступны после регистрации; существующие авторизация/алерты переиспользовать без дублирования системы.

**Согласованное функциональное ядро:** голосовой и текстовый ввод → распознавание после записи → извлечение intent → применение существующих фильтров → существующие карточки, раздельная понятная маркировка своих/сторонних → уточнения в рамках текущей сессии. Не расширять scope картографией/вакансиями.

**Решено по доступу:** гости — 3/сутки; авторизованные — 200/сутки; сохранение поисков и уведомления — **только после регистрации**; без ежемесячного денежного cap; ответы — только текстом; запись распознаётся после завершения.

**Сброс лимитов утверждён:** каждую ночь в 00:00 по `Europe/Madrid`, одновременно для гостей (3/сутки) и зарегистрированных (200/сутки). Скользящий интервал в 24 часа не применяется. Внутреннее время сервера может оставаться UTC: календарную границу вычислять с учётом часового пояса Испании.

**Примечание:** разделы 1–7 ниже сохраняют **исторический разбор исходного клиентского ТЗ**, а не новый перечень задач. Любые упоминания поиска вакансий, нового TOP-размещения, live ASR, карт/маршрутов, TTS, вопроса «регистрация разрешена?» или месячного лимита **отменены решениями выше**. При разработке ссылаться на таблицу раздела 0.

## 0.1. Предварительная схема API после решений владельца (2026-10-25)

> **Статус:** архитектурные предложения для Codex и обсуждения, не реализованные endpoint'ы/контракты. Внешние тарифы/модели пересматривать перед включением production.

**Внешние API (расчётные операции вне VPS):**

| Назначение | Основной кандидат | Запасной кандидат | Почему |
|---|---|---|---|
| Batch Speech-to-Text после записи | Groq `whisper-large-v3` | OpenAI `gpt-transcribe` | Мультиязычность. OpenAI поддерживает hints `languages/keywords` для Tenerife и смешанной речи; выбор после A/B на реальных 100 запросах |
| AI-обогащение описаний (фон) | DeepSeek `deepseek-flash` | заменяемый интерфейс другого LLM | Строго структурированные facts + evidence, без браузерного агента |
| Разбор пользовательской фразы и follow-up | DeepSeek `deepseek-flash` | заменяемый интерфейс LLM | Строгий intent JSON, hard/soft constraints, не доверять произвольным SQL/tool output |
| Извлечение кандидатов, лимиты и score | **Свой FastAPI + PostgreSQL/PostGIS + Redis** | — | Данные/фильтры/карточки обрабатываются сервером, без выгрузки каталога в модель |
| Карты/маршруты/вакансии/TTS | **Не подключаем** | — | Явно исключены владельцем; существующая карта объявлений остаётся |

**Официальные ссылки:** [Groq ASR](https://console.groq.com/docs/speech-to-text), [OpenAI file transcription](https://developers.openai.com/api/docs/guides/transcription), [DeepSeek models](https://api-docs.deepseek.com/quick_start/pricing/). Защита пользовательских/арендодательских персональных данных, условия поставщика и юрисдикция — отдельный необходимый production gate.

**Предлагаемые собственные backend-эндпоинты** (названия и JSON DTO предварительные):

- `GET /api/v1/ai-search/quota` → `{daily_limit,used,remaining,resets_at,authenticated}`. Серверная authority; frontend не ведёт доверенный счётчик.
- `POST /api/v1/ai-search/query` → либо текстовый JSON, либо audio multipart (через один внутренний orchestration pipeline); проверяет quota **до провайдерского вызова**, audio → ASR → validated intent → native filters → PostgreSQL cards → ответ текстом/карточками. Поддерживает session token + idempotency; **за одно пользовательское сообщение всегда максимум один debit**, даже если делает ASR и LLM.
- `POST /api/v1/ai-search/session` или продолжение через `query.session_id` → хранит только актуальное состояние фильтров на разумный TTL. Требования privacy/retention и anonymous session уточнить в реализации.
- Сохранённый поиск и оповещения — **переиспользовать текущие зарегистрированные API**, не создавать новую систему уведомлений.
- Отдельный **backend-only** job ingestion для `listing_ai_facts`; worker → sanitizer → DeepSeek → evidence check → canonical resolver → `listing_search_features`, без вызова LLM на каждую карточку и без публичного AI-enrichment endpoint.

**Квоты и отказоустойчивость:**
- Redis атомарный счётчик/резервация по анонимному cookie identifier или user_id + суткам; проверить транзакционность/конкурентность; анонимный cookie можно удалить, поэтому лимит 3 нельзя гарантировать по физическому человеку — использовать soft anti-abuse меры с privacy review.
- Лимиты аудиодлительности/байтов, request/token cap per call (техническая безопасность), concurrency/rate limiting и cost monitoring **допускаются**, но нет месячного денежного стоп-порога.
- При 429/5xx/ASR failure — retry с границами, не списывать квоту при сервисной ошибке; не удваивать списание при network retry; token/cost usage логировать без пользовательских текстов.
- Реальные данные/ключи только через сервер, никогда в React.
- `Permissions-Policy: microphone=()` сейчас выставлен backend/Nginx; для нового компонента потребуется разрешение микрофона на сайте с контролем и UX согласия.
- Все карты/карточки/TOP должны сохранить текущий DTO и поведение. Никаких новых Places/Routes/Live speech/voice output.

**Не реализовано:** внешние интеграции, backend endpoints, новая БД фактов, quota counters, acceptance benchmark. Проводить PR и staging QA отдельно.

## 1. Что клиент реально хочет

**Одна новая функция для уже работающего Ttest**: пользователь голосом или текстом задаёт условия аренды; помощник извлекает требования, применяет существующие фильтры, показывает сначала собственные объявления и дополнительно внешние с маркировкой, объясняет соответствие, поддерживает уточнения («с балконом»). На карте показывает полезные объекты, а если названо место работы/учёбы — маршрут.

Новые важные требования клиента:
- Комнаты и студии, long-term и tourist; расширение на квартиры/дома в будущем.
- Языки: RU/ES/EN, код-свитчинг и топонимы Tenerife; другие языки в auto-detect — условно.
- Состав проживающих обязателен; остальные параметры только при заявлении человеком; ≤1–2 уточнения.
- Editable chips: hard/soft, цена желаемая vs максимальная, подтверждённые/неизвестные условия.
- Результаты два круга: **внутренние** и **сторонние** (переход по внешнему URL; «сторонний сайт»), внутри — релевантность и свежесть.
- Sponsored TOP **отдельно** от органической AI-релевантности — это изменение существующей коммерческой логики; не делать до отдельного согласования и проверки контрактов.
- Карта/список в существующем UI, на каждой карточке 3–4 проверенных факта максимум; POI, при точных координатах — время/маршруты.
- Выделение странных чисел для подтверждения, ручная правка транскрипта и повтор записи.
- История: фильтры по умолчанию, без сохранения аудио; переписка только по добровольному выбору; saved search + notifications.
- Статусы объявления: confirmed/conditional/unknown/forbidden/conflict, никогда не маркировать неизвестное как «разрешено».

### Что НЕ следует автоматически трактовать как утверждённое
- Ответы 4–36 находятся **в составе сгенерированной редакции ТЗ**, клиент переслал её, но отдельного протокола утверждения не представлено.
- Исходные вопросы **1–3** отсутствуют в клиентском экспорте. **37–38** отсутствуют в блоке ответов; некоторые вопросы 14 и 23 в переписке представлены не полностью.
- «Стриминговая транскрипция» / TTS / охват всех языков, лимиты, бюджет, туристические даты/правила, гости без регистрации — не согласованы в конечном поведении.
- Позднейшее сообщение про «готовый код для поиска комнат, работы и жилья рядом с работой» расширяет scope до **поиска вакансий**, хотя основное ТЗ описывает только жильё и маршруты **до уже имеющейся работы**.

| MEDIUM | «Сохранять переписку по желанию» | Нужен account/anonymous lifecycle, retention/delete policy, оповещения, anti-abuse |

## 3. Подтверждённые текущие точки интеграции Ttest

- Есть FastAPI и POST `/api/v1/listings/search/cards`, PostgreSQL/PostGIS, текущие native filters, карта/список и существующая логика saved-search notifications.
- Импортёр сохраняет `external_listing_sources` с source URLs, content snapshots и canonical listing; separate evidence schema/worker пока не внедрены.
- В `backend/app/main.py` и `deploy/nginx.conf`: `Permissions-Policy: camera=(), microphone=()`, потребуется **точечно разрешить микрофон** для origin и проверить request size/security.
- Глобальный TOP tier сейчас влияет на сортировку; отдельный рекламный блок нельзя включать без продуктовой оценки.
- Присланный demo zip — не авторизованный компонент Ttest; требует ревью лицензий, угроз, секретов, качества тестов и совместимости, прежде чем обсуждать reuse.

## 4. Правовой и продуктовый check

Проверенные официальные источники (не юридическое заключение):
- Canary Islands [Ley 6/2025](https://www.boe.es/buscar/act.php?id=BOE-A-2025-26358) требует registration info для соответствующей tourist offer; официальный консолидированный текст указывает изменения [Ley 7/2026](https://www.extr.gobiernodecanarias.org/boc/2026/163/2922.html).
- [Ley 7/1995](https://www.boe.es/buscar/act.php?id=BOE-A-1995-12102) содержит режим muy grave и штрафы **€30 001–300 000** в соответствующих случаях; фразу «за любой отсутствующий номер автоматически штраф €30 001–300 000» считать упрощением, а не правилами enforcement.
- [EU 2024/1028](https://eur-lex.europa.eu/legal-content/EN/TXT/?uri=CELEX%3A32024R1028) применяется с **20 мая 2026**; требования к конкретному сервису зависят от его роли в совершении сделок и национальных регистрационных процедур.
- Сторонние URL и «мы не копируем фото» сами по себе не определяют все права на систематическое извлечение и использование данных. Проверить ToS, базы данных, авторское право, личные данные, условия провайдеров карт.

## 6. Вопросы заказчику, без которых нельзя считать ТЗ завершённым

1. **Поиск вакансий:** действительно входит в эту задачу или это побочная функция присланного демо, от которой отказываемся?
2. **Внешние сайты:** оставить нынешние импортированные preview-карточки с фотографиями и описанием или перейти на **только ссылку и минимальные подтверждённые метаданные**? Какие площадки разрешены?
3. **TOP:** отдельная рекламная зона относится и к уже оплаченным размещениям? Принимается ли изменение договора/коммерческих правил и позиций?
4. **Стриминг:** динамический текст во время речи — жёсткое требование MVP или допустима транскрипция после паузы/клика?
5. **Карты:** POI/маршруты для каждой карточки или только top-N по запросу? Какой budget и разрешённый provider?
6. **Tourist:** даты заезда/выезда обязательны? Какой режим tourist rooms и проверка registration требуется именно для ваших типов жилья?
7. **Анонимность:** неавторизованный голосовой поиск разрешён? Какие quotas/лимит затрат/retention?
8. **Дополнительные языки/TTS:** RU/ES/EN обязательны; auto-detect «другие» и ответ голосом — включать в MVP или позже?
9. **Вложенный ZIP:** прислать реальные `demo112233_source.zip`, `README.md`, `DEPLOY.md` для code/security/license review. Не запускать вслепую.
10. **Q1–3, Q37–38:** в клиентском материале нет однозначных ответов на первоначальные и заключительные вопросы; подтвердить соответствующую логику письменно.

## 7. Приоритетная позиция архитектора

- Реализовать как **нативный модуль Ttest**, не отдельный site-in-a-site.
- Не использовать browser-agent для каждого поиска, поскольку каталог уже есть; отдельно проверить права на импорт.
- Для MVP: **text intent + native filters + 2 группировки + session updates**. Голос, realtime transcript, POI, маршруты, TTS и уведомления — независимые флаги и бюджетные этапы.
- Не ставить zip или скрипты из непроверенного демо на текущий VPS.
- Не сливать #373 в main автоматически; сперва CI/review + согласованный план.

**Следующее действие:** вернуть заказчику список стоп-вопросов и получить архив+README/DEPLOY для отдельного аудита; параллельно продолжать каталожный read-only аудит и ADR.
